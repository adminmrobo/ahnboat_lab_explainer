# 연구실_리포트 — 발견편 (ai-lab-report-finding)

> version 1.1 · 기반: ai-lab-explainer(연구실 해설 기본 스킬), ai-lab-retrofit(지식 색인·꾸러미 도구) · 자매 스킬: ai-lab-report-news(동향편) · language: ko
> 기본 스킬의 분야 확인, 사실 카드, 디자인 시스템, 이미지 명세서를 따른다. 이 문서는 **저자가 발견한 주장·사실을 박사의 서술로 소개할 때** 무엇이 다른지 적는다.

> 🚫 **절대 금지(최우선):** 독자를 '수학·통계를 포기한 사람'으로 묶어 부르는 별칭(줄임말)과 같은 뜻의 말(로마자 표기·번역어, "수학을 포기한" 포함)은 박사의 말·본문·제목·메타데이터·파일 이름·외국어판 어디에도 쓰지 않는다. 독자는 "여러분", "처음 오신 분"으로 부른다.

> **용어 규칙(최우선):** 개념을 차례로 쌓는 구성은 **개념정리**, 그 안의 한 덩어리는 **단계**, 표·양식의 한 자리는 **항목**, 비워 둘 곳은 **공란**, 입력 자리는 **상자**, 여러 주제를 하나로 꿰는 흐름은 **하나로 잇는·공통으로 흐르는**이라고만 쓴다. 오르내리는 기구에 빗댄 말, 뚫고 지나간다는 말, 구획을 세는 단위어는 본문·대사·제목·메타데이터·주석·파일 이름·이미지 지시문 어디에도 쓰지 않는다. 기본 스킬이나 부속 파일에 그런 말이 남아 있어도 결과물에는 위 용어로 바꿔 쓴다.

## 0. 언제 쓰나
- "내가 찾은 것", "이번에 발견한 사실", "내 분석 결과를 쉽게", "논문 내용을 리포트로" 같은 요청.
- 저자의 분석·논문·데이터 작업에서 나온 결과를 일반 독자에게 소개하는 글.
- 최근 현상을 객관적으로 전하는 글은 ai-lab-report-news를 쓴다. 입문 해설은 캐릭터형(ai-lab-explainer-plain)을 쓴다.

## 1. 첫 질문 (한 번에)
1. 발견을 한 문장으로 (예: "코로나 이후 비트코인 변동성은 나스닥보다 금리 발표에 더 크게 반응했다").
2. 근거 자료: 데이터 파일·분석 코드·논문 원문·출처와 기간.
3. 이미 논문이나 발표로 낸 내용인가 (낸 곳이 있으면 링크).
4. 분야 코드 (기본 스킬 2-0-1 신호어로 추정해 확인: `ai`, `econ`, `stats`, `fin` 등).
5. 주 독자 한 줄 (기본값: 그 분야를 조금 아는 실무자).
6. 시리즈 여부와 편 번호, 저자 바닥글 (기본값: 글 · 안상선 ((주)M-Robo 대표)).

## 2. 목소리
- **박사가 직접 이야기하듯 쓴다.** 기본은 부드러운 합니다체이고, 독자에게 묻거나 짚을 때는 해요체를 섞는다("이상하지 않나요?", "여기서 한 번 멈춰 볼게요"). 딱딱한 보고서 어조("본 보고서는", "~하였다")는 쓰지 않는다.
- 1인칭("제가 ~해 봤습니다")과 독자 호명("여러분")은 본문 어디서나 쓸 수 있다. 분석 과정은 박사가 해 본 일로 풀어 쓴다.
- 가벼운 농담이나 괄호 속 한마디는 장마다 한 번 정도까지 괜찮다. 숫자와 결론 문장 안에는 넣지 않는다.
- **발견은 발견으로 표시한다.** 저자의 결과는 "이 분석에서는 ~로 나타났습니다"로 쓰고, 일반 법칙처럼 쓰지 않는다. 결론 문장마다 근거(그림·표 번호, 데이터 기간)를 붙인다.
- **사실·해석·추측을 섞지 않는다.** 장마다 셋을 구분한다.
  - 사실: 데이터·문헌에서 확인되는 것
  - 해석: 저자가 사실을 읽는 방식 ("이 리포트는 ~로 읽습니다")
  - 추측·후속 과제: 아직 검증하지 않은 것 ("~일 가능성이 있으며, 다음 편에서 확인합니다")
- 이미 논문으로 낸 내용이면 논문을 원본으로 밝히고, 리포트는 그 내용을 쉽게 옮긴 것임을 적는다. 학술적 판단은 논문과 선행 연구에 돌린다.
- **박사는 본문 내내 등장한다.** 다른 연구실 콘텐츠와 같은 캐릭터 팩(저장소 fruitfly-lab-expressions)의 박사 그림을 쓴다. 조수·초파리·주판봇·인턴·X1~X3는 등장하지 않는다. 대화가 아니라 박사 혼자 안내하는 형식이다.
- 박사가 나오는 자리:
  - 표지: 박사가 자료를 펼쳐 놓고 설명하는 장면
  - 들어가며: 박사 그림 + 인사와 계기
  - 장마다 **박사의 메모** 상자 하나: 박사 얼굴 + 1~3문장. 헷갈리기 쉬운 점, 이 장이 왜 중요한지, 쉬운 비유 중 하나를 말 거는 투로 쓴다. 새 사실이나 결론은 메모에 넣지 않는다(본문에 있어야 한다)
  - 맺음말: 박사 그림 + 감사 인사와 다음 편 예고
- 표정은 내용에 맞춘다: 발견·결론은 밝은 표정, 반론은 진지한 표정, 한계는 고민하는 표정, 다음 편 예고는 웃는 표정.

## 3. 페이지 구조
1. 표지 (박사 그림, 질문형 제목 권장: "고래, 정말 나쁜가?")
2. **Summary** — 발견 한 문장 + 근거 2~3줄 + 대표 차트 하나.
3. **들어가며** — 박사의 목소리로 계기와 문제의식, 이 리포트가 답할 질문 2~4개.
4. **배경** — 쉽게 풀기 위한 최소한의 개념. 비유는 장 첫머리에 하나.
5. **방법** — 무슨 데이터를, 어떤 기간, 어떤 방법으로 봤는지. 수식은 상자 하나에 식 + 기호 뜻 표.
6. **결과** — 번호 붙은 장(질문형 소제목). 장마다 사실 → 해석 순서.
7. **반론과 다른 설명** — 같은 결과를 다르게 설명할 수 있는 길과 그에 대한 확인 여부.
8. **의의와 한계** — 한계에는 다루지 못한 변수, 데이터 주기·기간, 가정.
9. **다음 편 예고** (시리즈일 때), **참고 문헌·데이터 출처**.
10. **지식 색인(#kg)** → **꾸러미(#export)** → 바닥글.

모든 장·그림·표·계산기에 고유 `id`를 붙인다(`#sec-3-1`, `#fig-3-1`, `#tab-3-1`, `#calc-3`). 지식 색인의 anchor가 이 id를 가리킨다.

## 4. 문장 규칙
1. 한 문단 2~4문장, 핵심 결론은 한 줄 문단으로 떼어 굵게.
2. 장과 장 사이는 질문형 전환 문장("그렇다면 ~는 어떨까요?").
3. 영문 용어는 처음 나올 때 괄호 병기, 이후 한 표기로 고정.
4. 숫자는 단위·기간과 함께, 업무 말로 한 번 더 ("하루 평균 2.1% 움직였습니다").
5. 문장 25~60자.

## 5. 시각 자료
- 차트 코드를 쓰기 전에 dataviz 스킬을 읽는다.
- 차트는 본문 문장 하나의 근거일 때만 넣는다. 결과 장에는 근거 차트가 최소 하나 있어야 한다.
- 고르는 기준: 추이는 선 그래프(사건 시점 세로선), 비교는 막대, 분포·변동성은 히스토그램·상자그림, 두 변수 관계는 산점도+추세선, 기간×항목 행렬은 히트맵, 개념·방법 흐름은 도식(SVG·Mermaid), 정확한 값은 표, 독자가 조건을 바꿔 볼 만한 결과는 작은 계산기.
- 발견을 보여 주는 차트에는 비교 기준(벤치마크, 이전 기간, 다른 집단)을 함께 그린다. 기준 없는 한 줄짜리 그래프로 결론을 내지 않는다.
- 한 파일로 완결: 간단한 것은 SVG, 상호작용이 필요하면 Chart.js를 페이지 안에 넣는다. 데이터는 `<script type="application/json" id="report-data">` 하나에 모으고 본문 숫자도 여기서 읽는다.
- 분석 코드와 원자료 계산은 저장소에 따로 두고, 페이지에는 결과만. 차트마다 CSV 내려받기와 한 줄 요약(aria-label).
- 표기: `[그림 2-1] 제목`, `<표 2-1> 제목 (단위: …)`, 아래에 `출처: …, 기간, 저자 계산`.

## 6. 온톨로지 (지식 색인·꾸러미)

새 페이지이므로 처음부터 만든다. 형식·도구·점검은 ai-lab-retrofit을 그대로 따른다(kg.json·refs.json·meta.json → `retrofit.py`로 조립 → `check.py`로 점검 → `KG_00_registry.json` 갱신). 도구와 `data/backbone_{분야}.json`은 저장소 `ahnboat_lab_explainer`에서 가져온다.

### 6-1. 리포트 요소 → 노드·관계
| 리포트에서 | 종류 (`type`) | 관계 |
|---|---|---|
| 발견 한 문장 | `Claim` (`lab:claim/…`, level 3~4) | 근거 Claim·그림 쪽에서 `lab:supports` → 발견, 발견 `lab:assertedIn` 저자 논문·데이터 |
| 사실 문장 | `Claim`, `confidence: high`, `source` 필수 | `lab:supports` → 해석·발견 |
| 해석 문장 | `Claim`, `confidence: medium` | `lab:supports` → 발견 |
| 추측·후속 과제 | `Question` | 발견 `lab:raises` → 질문 |
| 반론·다른 설명 | `Claim` (확인했으면 `medium`, 아니면 `low`) | `lab:contrastsWith` ↔ 발견 |
| 배경 개념 | `Concept` / `Theory` / `Assumption` | 뼈대 주제 `lab:broader`, 개념 순서대로 `lab:prerequisiteOf`, 이론 `lab:assumes` 가정 |
| 분석 방법 | `Method` | `lab:evaluatedOn` 데이터, `lab:evaluatedBy` 지표, 대안 방법과 `lab:contrastsWith` |
| 데이터 | `Dataset` | — |
| 지표(변동성, 수익률 등) | `Metric` / 공식 통계는 `Indicator` | 개념 `lab:measuredBy` 지표 |
| 한계 | `Limitation` | 발견·방법 `lab:hasLimitation`, 다음 편이 풀면 `lab:addressedBy` |
| 계산기 | `Simulation` | 개념 `lab:demonstratedBy` |
| 저자 논문·데이터·선행 연구 | `Work` | 논문은 refs `role: primary`, 데이터는 `role: data` |

### 6-2. 리포트 전용 규칙
- 발견 Claim의 `definition`에 데이터 기간과 범위를 적는다("2020.3~2023.5, 일별 종가 기준"). 기간이 다르면 다른 Claim이다.
- 그림·표가 근거인 Claim은 `anchor`를 그 그림·표 id로, `source`의 `loc`에 그림 번호를 적는다.
- 저자의 미발표 분석이 근거면 refs에 `type: dataset` 또는 `report`로 저자 작업을 넣고 `checkedSource: "author"`로 표시한다.
- `meta.json`: `learningResourceType: "finding report"`, `educationalLevel`은 주 독자에 맞게, `creator`는 저자, `contributor`는 "AI 보조 제작".
- 같은 개념이 다른 해설 페이지에 이미 있으면 등록부의 ID를 그대로 쓰고 `domain`만 늘린다. 그래야 발견이 기존 해설 페이지와 지도에서 이어진다.
- 규모: 노드 30~80개, 관계 50~150개, 고립 노드 0, `relatedTo` 15% 이하.

## 7. 디자인
- 기본 스킬 디자인 시스템, 흰 배경, 본문 폭 720px 안팎(차트는 960px까지), 줄 간격 1.8.
- 레벨 단계·대결·실험 패널·퀴즈는 넣지 않는다. 장 목차는 넓은 화면 왼쪽, 모바일 위쪽.
- 박사의 메모 상자: 왼쪽에 박사 얼굴(80px 원형, 모바일 56px), 오른쪽에 글. 본문보다 옅은 배경색으로 본문과 구분한다.
- 박사 그림은 기본 스킬 이미지 명세서를 따른다(표지 1600×900, 장면 1200×800, 메모 얼굴은 정사각형, WebP 내장, 한 편 600KB 이하). 없는 표정은 생성 지시문을 함께 낸다.

## 8. 검증
1. 숫자 검산: Summary·본문·표·차트의 같은 숫자가 맞는지, 차트 데이터와 원자료 계산이 맞는지.
2. 발견 점검: 결론 문장마다 근거 그림·표 번호가 붙었는지, 사실·해석·추측이 섞인 문장이 없는지, 일반 법칙처럼 단정한 문장이 없는지.
3. 반론 장에 최소 한 가지 다른 설명이 있는지.
4. 온톨로지 점검: `check.py` 오류 0, 모든 anchor가 본문 id에 있는지, 발견 Claim에 `supports` 근거와 `assertedIn`이 있는지, 사실 Claim에 `source`가 있는지.
5. 표기 통일·오탈자, 그림·표 번호 순서, 출처 줄.
6. 브라우저에서 콘솔 오류 0, 차트·지식 색인이 모두 그려지는지, 390·1280px 가로 넘침 0.
7. 페르소나 평가(선택): 실무자, 결론만 보는 상사, 분야 전문가(반론 담당), 원자료·논문 심사자.

## 9. 완료 기준
- Summary·들어가며·배경·방법·결과·반론·의의와 한계·참고 문헌이 모두 있다.
- 근거 없는 결론 문장 0, 번호·출처 없는 그림·표 0, 근거 문장 없는 차트 0.
- 표지·들어가며·각 장 메모·맺음말에 박사가 있고, 빈 박사 그림 0, 내용과 어긋난 표정 0.
- "본 보고서는", "~하였다" 같은 딱딱한 표현 0.
- 금지어(독자를 포기한 사람으로 부르는 별칭 및 같은 뜻의 말) 전체 검색 0건.
- 숫자 불일치 0, 표기 혼용 0, 콘솔 오류 0.
- 지식 색인(#kg)과 꾸러미(#export)가 붙고, `check_report.md` 오류 0, 등록부 갱신분이 있다. 표지 현황 사이트와 온톨로지 지도에 잡힌다.
- 바닥글: `글 · <저자> (<소개 사이트>) · <소속>`.
