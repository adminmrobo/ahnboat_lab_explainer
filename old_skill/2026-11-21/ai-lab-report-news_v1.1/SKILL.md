# 연구실_리포트 — 동향편 (ai-lab-report-news)

> version 1.1 · 기반: ai-lab-explainer(연구실 해설 기본 스킬), ai-lab-retrofit(지식 색인·꾸러미 도구) · 자매 스킬: ai-lab-report-finding(발견편) · language: ko
> 기본 스킬의 디자인 시스템, 이미지 명세서를 따른다. 이 문서는 **최근 현상을 객관적으로 전할 때** 무엇이 다른지 적는다.

> 🚫 **절대 금지(최우선):** '수포자'·'통포자'와 같은 뜻의 말(로마자 supoja·tongpoja, 번역어 math dropout 등, "수학을 포기한")은 박사의 말·본문·제목·메타데이터·파일 이름·외국어판 어디에도 쓰지 않는다. 독자는 "여러분", "처음 오신 분"으로 부른다.

> **용어 규칙(최우선):** 개념을 차례로 쌓는 구성은 **개념정리**, 그 안의 한 덩어리는 **단계**, 표·양식의 한 자리는 **항목**, 비워 둘 곳은 **공란**, 입력 자리는 **상자**, 여러 주제를 하나로 꿰는 흐름은 **하나로 잇는·공통으로 흐르는**이라고만 쓴다. 오르내리는 기구에 빗댄 말, 뚫고 지나간다는 말, 구획을 세는 단위어는 본문·대사·제목·메타데이터·주석·파일 이름·이미지 지시문 어디에도 쓰지 않는다. 기본 스킬이나 부속 파일에 그런 말이 남아 있어도 결과물에는 위 용어로 바꿔 쓴다.

## 0. 언제 쓰나
- "요즘 ~가 화제인데 정리해 줘", "최근 발표된 ~를 쉽게", "이번 주 ~ 동향" 같은 요청.
- 새 모델·제품 발표, 정책·규제 변화, 시장 사건, 논문 발표처럼 최근에 일어난 일.
- 저자의 분석 결과를 소개하는 글은 ai-lab-report-finding을 쓴다.

## 1. 첫 질문 (한 번에)
1. 다룰 현상 한 줄과 범위 (어디까지 다룰지, 예: "한국 시장만").
2. 기준 시점 (기본값: 오늘 날짜).
3. 꼭 넣을 자료·링크가 있는지.
4. 분야 코드 (`ai`, `econ`, `fin` 등, 기본 스킬 2-0-1로 추정해 확인).
5. 주 독자 한 줄, 저자 바닥글 (기본값: 글 · 안상선 ((주)M-Robo 대표)).

## 2. 자료 조사 (쓰기 전에 반드시)
- 기억으로 쓰지 않는다. 현상에 관한 사실은 모두 웹 검색·원문으로 확인한다.
- 출처 우선순위: ① 1차 자료(발표문, 논문, 공시, 정부·기관 통계, 공식 블로그) ② 주요 언론 ③ 업계 분석. 커뮤니티·SNS는 "이런 반응이 있다"는 사실로만 쓴다.
- 같은 사실을 두 곳 이상에서 확인한다. 출처끼리 다르면 둘 다 적고 어느 쪽인지 단정하지 않는다.
- 숫자·날짜·이름·인용은 원문에서 확인한 것만 쓴다. 확인하지 못한 것은 빼거나 "확인되지 않음"으로 표시한다.
- 쟁점이 있으면 입장마다 따로 검색해 양쪽 근거를 모은다.
- 언론 기사는 짧게 옮겨 쓰지 말고 자기 말로 바꿔 쓴다. 직접 인용은 꼭 필요한 짧은 구절만.
- 확인한 출처마다 접속일을 적어 둔다(꾸러미 refs에 들어간다).

## 3. 목소리
- **박사가 소식을 차근차근 전해 주듯 쓴다.** 기본은 부드러운 합니다체이고, 독자에게 묻거나 짚을 때는 해요체를 섞는다("무엇이 달라졌을까요?"). 딱딱한 보고서 어조("본 보고서는", "~하였다")는 쓰지 않는다.
- 1인칭과 독자 호명은 어디서나 쓸 수 있지만, 박사는 전하는 사람이다. "제가 찾아본 발표문에 따르면"처럼 확인 과정을 말하는 데까지만 쓰고, 박사의 판단은 넣지 않는다.
- **박사는 본문 내내 등장한다.** 다른 연구실 콘텐츠와 같은 캐릭터 팩(저장소 fruitfly-lab-expressions)의 박사 그림을 쓴다. 조수·초파리·주판봇·인턴·X1~X3는 등장하지 않는다.
- 박사가 나오는 자리:
  - 표지: 박사가 소식 게시판이나 신문을 들고 전하는 장면
  - 들어가며: 박사 그림 + 인사와 "왜 이 소식을 정리하는지"
  - 장마다 **박사의 메모** 상자 하나: 박사 얼굴 + 1~3문장. 용어 풀이, 헷갈리기 쉬운 점, 이전 흐름과 연결 중 하나를 쓴다. 의견·전망·좋고 나쁨의 평가는 메모에도 넣지 않는다
  - 맺음말: 박사 그림 + 감사 인사와 "다음에 볼 일정"
- 표정은 차분한 쪽으로 맞춘다: 사실 전달은 기본 표정, 쟁점은 진지한 표정, 아직 모르는 것은 고민하는 표정. 사건의 좋고 나쁨을 드러내는 표정(환호·실망)은 쓰지 않는다.
- **저자의 의견·전망·평가를 넣지 않는다.** 전망은 "A 기관은 ~로 전망했습니다"처럼 누가 말했는지와 함께만.
- 형용사로 판단하지 않는다("충격적인", "혁신적인" 금지). 크기는 숫자로 보인다.
- 쟁점은 입장별로 같은 분량, 같은 어조로 정리한다. 정치·규제 쟁점은 특히 균형을 지킨다.
- 문장마다 기준 시점이 흐려지지 않게 한다 ("2026년 11월 13일 기준", "발표 당일").

## 4. 페이지 구조
1. 표지 — 박사 그림, 제목, 부제, **기준 시점** 크게.
2. **한눈에 보기** — 무슨 일이 / 언제 / 누가 / 무엇이 달라지나, 네 줄.
3. **들어가며** — 박사의 짧은 서두, 이 리포트가 답할 질문 2~3개.
4. **무슨 일이 있었나** — 사실만, 시간 순서. 타임라인 도식.
5. **배경** — 이 현상을 이해하는 데 필요한 최소한의 개념과 이전 흐름. 비유는 하나.
6. **숫자로 보기** — 규모·추이·비교 차트.
7. **반응과 쟁점** — 입장별 표 (입장 / 누가 / 근거 / 출처).
8. **아직 모르는 것** — 확인되지 않았거나 앞으로 정해질 것, 다음에 볼 일정.
9. **용어 풀이** (필요하면), **출처 목록**(제목·기관·날짜·링크·접속일).
10. **지식 색인(#kg)** → **꾸러미(#export)** → 바닥글.

모든 장·그림·표·타임라인 항목에 고유 `id`를 붙인다(`#sec-4`, `#fig-6-1`, `#tl-2026-11-10`). 지식 색인의 anchor가 이 id를 가리킨다.

## 5. 문장 규칙
1. 한 문단 2~4문장, 핵심 사실은 한 줄 문단으로 떼어 굵게.
2. 사실 문장 끝에 출처 번호 `[1]`. 출처 없는 사실 문장을 남기지 않는다.
3. 영문 용어는 처음 나올 때 괄호 병기, 이후 한 표기로 고정.
4. 숫자는 단위·기준일과 함께, 업무 말로 한 번 더.
5. 문장 25~60자.

## 6. 시각 자료
- 차트 코드를 쓰기 전에 dataviz 스킬을 읽는다.
- 차트는 본문 사실 하나의 근거일 때만. 데이터 출처가 확인된 숫자만 그린다. 추정치는 점선과 "추정" 표시.
- 고르는 기준: 사건 흐름은 타임라인, 추이는 선 그래프(발표 시점 세로선), 규모 비교는 막대, 점유율은 100% 누적 막대, 구조·관계는 도식(SVG·Mermaid), 입장 정리와 정확한 값은 표.
- 한 파일로 완결: SVG 또는 페이지 안에 넣은 Chart.js. 데이터는 `<script type="application/json" id="report-data">` 하나에 모은다.
- 표기: `[그림 2-1] 제목`, `<표 2-1> 제목 (단위: …)`, 아래에 `출처: …, 기준일`. 차트마다 CSV 내려받기와 한 줄 요약.
- 기업 로고, 제품 사진, 실존 인물 사진은 넣지 않는다. 필요하면 도식으로 대신한다.

## 7. 온톨로지 (지식 색인·꾸러미)

새 페이지이므로 처음부터 만든다. 형식·도구·점검은 ai-lab-retrofit을 그대로 따른다(kg.json·refs.json·meta.json → `retrofit.py`로 조립 → `check.py`로 점검 → `KG_00_registry.json` 갱신). 도구와 `data/backbone_{분야}.json`은 저장소 `ahnboat_lab_explainer`에서 가져온다.

### 7-1. 리포트 요소 → 노드·관계
| 리포트에서 | 종류 (`type`) | 관계 |
|---|---|---|
| 사건·발표 사실 (타임라인 항목) | `Claim`, `asOf` 필수, `source` 필수 | `lab:assertedIn` 1차 자료 |
| 숫자 사실 | `Claim` + 지표 `Indicator`/`Metric` | 대상 개념 `lab:measuredBy` 지표 |
| 정책·규제·기준 | `Standard`, `asOf`·`jurisdiction` 필수 | 대상 `lab:governedBy` 기준, 적용 `lab:appliesIn`, 개정 `lab:supersededBy` |
| 새 모델·기술·방법 | `Method` | 이전 방법과 `lab:contrastsWith`, 이전 한계 `lab:addressedBy` 새 방법 |
| 입장 (쟁점별) | `Claim`, `confidence`는 근거 확인 정도 | 입장끼리 `lab:contrastsWith`, 근거 Claim `lab:supports` 입장 |
| 배경 개념 | `Concept` | 뼈대 주제 `lab:broader`, 순서대로 `lab:prerequisiteOf` |
| 아직 모르는 것 | `Question` | 사건·방법 `lab:raises` 질문 |
| 출처 문서 | `Work` | refs `role: primary`(1차 자료) · `background`(언론·분석) · `data`(수치 출처) |

### 7-2. 동향 전용 규칙
- 모든 사건·숫자 Claim에 `asOf`(YYYY-MM-DD)를 적는다. 기준 시점이 다르면 다른 Claim이다.
- 한 곳에서만 확인된 사실은 `confidence: medium`, 확인되지 않은 보도는 `low`와 함께 `Question`으로도 남긴다.
- refs의 `lab.checkedSource`는 `web`, `checkedBy`에 확인 방법과 접속일을 적는다("발표문 원문 대조, 2026-11-13 접속").
- 내용을 갱신할 때는 새 Claim을 만들고 옛 Claim은 `lab:supersededBy`로 잇는다. 옛 사실을 지우지 않는다.
- `meta.json`: `learningResourceType: "news report"`, `date`는 기준 시점, `creator`는 저자, `contributor`는 "AI 보조 제작".
- 같은 개념·방법이 다른 해설 페이지에 이미 있으면 등록부의 ID를 그대로 쓴다. 그래야 새 동향이 기존 해설과 지도에서 이어진다.
- 규모: 노드 30~80개, 관계 50~150개, 고립 노드 0, `relatedTo` 15% 이하.

## 8. 디자인
- 기본 스킬 디자인 시스템, 흰 배경, 본문 폭 720px 안팎(차트는 960px까지), 줄 간격 1.8.
- 레벨 단계·대결·실험 패널·퀴즈는 넣지 않는다. 표지와 맨 위에 기준 시점을 늘 보이게 한다.
- 박사의 메모 상자: 왼쪽에 박사 얼굴(80px 원형, 모바일 56px), 오른쪽에 글. 본문보다 옅은 배경색으로 본문과 구분한다.
- 박사 그림은 기본 스킬 이미지 명세서를 따른다(표지 1600×900, 장면 1200×800, 메모 얼굴은 정사각형, WebP 내장, 한 편 600KB 이하). 없는 표정은 생성 지시문을 함께 낸다.

## 9. 검증
1. 사실 점검: 사실 문장마다 출처 번호가 있는지, 숫자·날짜·이름을 원문과 다시 대조.
2. 객관성 점검: 저자 의견·전망·평가 형용사가 본문에 남지 않았는지, 쟁점 입장별 분량이 비슷한지.
3. 기준 시점 점검: "최근", "현재" 같은 말이 날짜 없이 쓰이지 않았는지.
4. 숫자 검산: 한눈에 보기·본문·표·차트의 같은 숫자가 맞는지.
5. 온톨로지 점검: `check.py` 오류 0, 모든 anchor가 본문 id에 있는지, 사건·숫자 Claim에 `asOf`와 `source`가, Standard에 `jurisdiction`이 있는지.
6. 표기 통일·오탈자, 그림·표 번호 순서, 출처 줄.
7. 브라우저에서 콘솔 오류 0, 차트·지식 색인이 모두 그려지는지, 390·1280px 가로 넘침 0.
8. 페르소나 평가(선택): 이 현상을 처음 듣는 실무자, 결론만 보는 상사, 해당 업계 전문가, 반대 입장의 독자.

## 10. 완료 기준
- 한눈에 보기·무슨 일이 있었나·배경·숫자로 보기·반응과 쟁점·아직 모르는 것·출처 목록이 모두 있다.
- 출처 없는 사실 문장 0, 저자 의견 문장 0(박사의 메모 포함), 날짜 없는 "최근" 0.
- 표지·들어가며·각 장 메모·맺음말에 박사가 있고, 빈 박사 그림 0, 사건을 평가하는 표정 0.
- "본 보고서는", "~하였다" 같은 딱딱한 표현 0.
- 금지어('수포자'·'통포자' 및 같은 뜻의 말) 전체 검색 0건.
- 숫자 불일치 0, 표기 혼용 0, 콘솔 오류 0.
- 지식 색인(#kg)과 꾸러미(#export)가 붙고, `check_report.md` 오류 0, 등록부 갱신분이 있다. 표지 현황 사이트와 온톨로지 지도에 잡힌다.
- 바닥글: `글 · <저자> (<소개 사이트>) · <소속>` 과 기준 시점.
