# 연구실 확장 스킬북 — 업데이트용 (ai-lab-extend)

> version 1.1 · 대상: ai-lab-explainer로 이미 만든 페이지(어느 시리즈든) · 교수법 스킬(concept-first-teaching) 기본 탑재 · language: ko
> 기본 스킬의 틀(히어로 → 등장인물 → 레벨 단계 → 대결 → 정리 → 지식 색인·꾸러미)은 건드리지 않는다. 단계 **앞**에 도입·대화를, 단계 **끝**에 코드 상자를 끼우고, 문장을 쉬운 말로 다시 쓴다.
> **용어 규칙(최우선):** 개념을 차례로 쌓는 구성은 **개념정리**, 그 안의 한 덩어리는 **단계**, 표·양식의 한 자리는 **항목**, 비워 둘 곳은 **공란**, 입력 자리는 **상자**, 여러 주제를 하나로 꿰는 흐름은 **하나로 잇는·공통으로 흐르는**이라고만 쓴다. 오르내리는 기구에 빗댄 말, 뚫고 지나간다는 말, 구획을 세는 단위어는 페이지·문서·대사·주석·파일 이름·이미지 지시문 어디에도 쓰지 않는다. 기본 스킬이나 부속 파일에 그런 말이 남아 있어도 결과물에는 위 용어로 바꿔 쓴다. 업데이트하는 기존 페이지에 그런 말이 있으면 함께 바꾼다.

## 0. 언제 쓰나
- "내용은 맞는데 어렵다", "처음부터 모델이 나와서 이해가 안 된다", "코드가 본문에 있어서 더 어렵다", "빽빽해서 답답하다"는 반응이 나왔을 때.
- 독자를 비전공자(예: AI를 모르는 경영·사무직, 일반인, 학생)로 바꿔야 할 때.
- 처음 만드는 페이지라면 이 스킬 대신 `ai-lab-explainer-plain`을 쓴다.

## 1. 먼저 정할 것 (한 번에 묻기)
1. 주 독자 한 줄 (예: "AI를 전혀 모르는 경영·사무직").
2. 대상 페이지 범위 (시리즈 전체 / 일부 주차).
3. 원자료(교안·논문)와 다른 값이 있는지. 저자가 원자료 쪽이 틀렸다고 확인하면 **"바꾼다"**로 쓴다(5장).
4. 저자 바닥글 표기와 소개 사이트 주소.
5. 커밋 규칙(작성자·공동 작성자 표기 제한이 있는지).

## 1-1. 교수법 스킬 기본 탑재 — 박사는 친절한 교육자 (v1.1)

업데이트할 때 concept-first-teaching의 검토 모드(7개 원칙 채점 → 보완)를 함께 돌린다. 박사는 캐릭터 성격·말투를 그대로 두고 **친절한 교육자** 역할을 함께 맡는다: 단계를 현장 질문으로 열고, 공식보다 "왜"를 먼저 말하고, 조수의 수식 질문에 기호 하나씩 답하고, 주판봇의 성급한 확신을 "AI 결과"로 놓고 확인 질문을 던지고, 풀이를 업무 해석 문장으로 마무리하고, 막히기 쉬운 곳에서 안심 신호를 준다. 기존 박사 대사는 이 역할에 맞게 다시 쓰거나 더할 수 있다(캐릭터 설정·표정 체계는 그대로).

### 🚫 절대 금지 — 최우선 규칙
- **독자를 '수학·통계를 포기한 사람'으로 묶어 부르는 별칭(줄임말)은 어떤 대사에도, 페이지의 어떤 글자에도 나오지 않는다.** 제목·본문·말풍선·퀴즈·alt·메타데이터·지식 색인·꾸러미·파일 이름·저장소 이름·외국어판 포함. 그 별칭의 로마자 표기·번역어·"수학을 포기한" 같은 표현도 금지.
- 기존 페이지에 이런 말이 있으면 이번 업데이트에서 지운다.
- 수정본 파일 이름에도 이 말을 쓰지 않는다.

## 2. 작업 순서
1. **진단 — 페르소나 평가**(persona-review 스킬): 독자 쪽에 무게를 둔 6명(입문 독자, 그 독자의 상사, 숫자에 강한 실무자, 성인 학습자, 원자료 저자, 분야 전문가). 페이지마다 코드 표시 수, `<pre>` 수, 영어 토큰 수, 용어집에 없는 약어를 세어 근거로 삼는다.
2. **원자료와 다른 값 확정**: "정정", "오기로 보임", "다른 분할로 보임" 같은 추정형을 모두 "원자료의 A를 이 페이지에서는 B로 바꿉니다"로 바꾼다. 관련 TODO도 지운다.
3. **본문 전체 다시 쓰기**(5장): 단계마다 「머신러닝에서는(○○에서는)」 단락, 풀이 목록, 한계 문장, 정리 카드까지. 한 주차만이 아니라 시리즈 전체를 같은 기준으로 본다. 교수법 기준표로 채점해 2점 미만 항목을 함께 고치고, 박사의 교육자 대사(1-1)를 단계마다 넣는다.
4. **블록 끼우기**(3장): 3줄 상자 → 약어 풀이 → 왜 이 모델 + 조수 수식 → 단계 대화 → 코드 접기.
5. **여백 완화**(4장).
6. **바닥글**: `글 · <저자> (<소개 사이트>) · <소속>`, 기계용 저자 정보(JSON-LD creator)에 같은 `url`.
7. **점검**(6장) → 커밋.

## 3. 끼우는 블록
문구는 페이지 HTML에 직접 쓰지 말고 **데이터 파일**에 모은 뒤 빌드 때 끼운다. 사용자가 문구만 고칠 수 있게 하기 위해서다.

| 블록 | 위치 | 내용 | 권장 데이터 파일 |
|---|---|---|---|
| 처음 오신 분께 — 이 페이지를 3줄로 | `</header>` 바로 뒤 `section#plain` | 무엇을 / 왜 중요한가 / 업무에서는 + "코드·수식을 몰라도 됩니다" 한 줄 | plain.py `PLAIN[주차]=(무엇,왜,업무,코드있음)` |
| 영어 약어 풀이 | 3줄 상자 안 `details.abbr` | 페이지 본문에서 대문자 약어를 자동으로 찾아, 사전에 있는 것만 우리말 이름 + 한 줄 설명 | abbr.py `ABBR[약어]=(이름,설명)` |
| 왜 이 모델(방법)을 쓰나 | 모델·수식 단계 맨 앞, `.pair` 앞 `div.easy > .ez-why` | 문제 상황 → 앞 방법의 한계 → 이 모델의 해법(굵게) + 「쉽게 말하면」 비유 한 줄 | easy.py `EASY[(주차,단계)]` |
| 수학 수식을 어려워하는 조수가 대신 물어봅니다 | 같은 줄 오른쪽 `.ez-math` | 조수 질문(asst_shock) → 「학교 수학으로 보면」 → 식 조각 표(식, 읽는 법) → 「숫자로 한 번 해 보기」 → 조수 코멘트(asst_spark) | easy.py `ASK[(주차,단계)]=(질문,코멘트)` |
| 단계 대화 | 단계마다 실험 패널 바로 앞 `div.dialog.lvtalk` | 2~3줄. 박사 질문 · 주판봇 성급한 확신 · 초파리 의심과 "이걸 눌러 봐" · 조수 보고 | talk.py `DLG[(주차,단계)]=[(who,mood,text)]` |
| 교안의 파이썬 코드로 보면 (몰라도 됩니다) | 단계 끝, 퀴즈 앞 `details.code > dl.codemap` | 코드 한 줄(dt) + 뜻 한 줄(dd) | 페이지 본문 |

규칙
- "왜/수식" 상자는 모델·수식이 있는 단계에만. 모델 단계는 "왜 이 모델을 쓰나", 나머지는 "왜 이 방법을 쓰나".
- 수식 상자 제목에 "중·고등학생 눈높이" 같은 표현을 쓰지 않는다. 눈높이는 조수의 질문으로 보여 준다.
- 「학교 수학으로 보면」은 교과 단원 이름으로 잇는다: 일차함수, 피타고라스 정리, 이차함수, 거듭제곱, 지수·로그, 등비급수, 조건부 확률, 독립시행, 계차수열·점화식, 합성함수, 미분(기울기).
- 「숫자로 한 번 해 보기」의 값은 반드시 코드로 검산한 뒤 넣는다. 페이지의 실험·공식과 같은 정의(예: 분산을 n으로 나누는지)를 쓴다.
- 조수의 질문은 그 수식에서 실제로 막히는 지점(기호, 제곱하는 이유, 나누는 이유)을 묻고, 코멘트는 자기 말로 한 줄 정리한다. 단계마다 다르게 쓴다.
- 대화 속 버튼·슬라이더 이름은 페이지의 실제 컨트롤 이름과 맞춘다(JS의 radio·label을 확인).
- 대화에 쓴 캐릭터 표정 키는 SPRITE에 함께 싣는다.

## 5. 문장 쓰기 규칙
1. **동작 먼저, 이름은 괄호로.** "도미와 빙어 비율이 똑같이 들어가게 나눕니다(층화)."
2. **나열 대신 번호.** 이름만 잇지 말고 ① ② ③으로 하나씩 푼다.
3. **기호는 뜻과 함께.** ρ, σ, p, α가 처음 나오면 "모델끼리 닮음(ρ)"처럼.
4. **원자료와 다른 값은 "바꾼다".** 추정형 금지.
5. **본문에 코드 금지.** 함수·속성·인자 이름(`reshape(-1, 1)`, `(42,)`, `random_state`, `predict_proba`, `feature_importances_`, `plt.pie()`, `annot=True`)은 쉬운 말로 바꾸고 코드는 접기 상자로. 단계 제목 아래 "코드: …" 꼬리표도 "방법: …", "설정: …", "일상: …"으로.
6. **숫자는 업무 말로.** "오차 25" → "평균 25g 빗나감", "AUC 0.5" → "동전 던지기 수준".
7. **설정값 이름도 우리말 라벨로.** 슬라이더 라벨 `random_state` → "섞는 순서 번호".

바꾼 예
| 원래 | 바꾼 뒤 |
|---|---|
| (42,) 1차원 배열을 reshape(−1, 1)로 (42, 1) 2차원으로 | 길이 42개를 42줄짜리 세로 표로 세워서 넣습니다 |
| 교란 변수를 고정 | 숨은 원인이 같은 사람끼리 비교 |
| lag 1 ACF | 한 시점 전과의 닮음 |
| 원자료 오기로 보임 | 원자료의 A를 이 페이지에서는 B로 바꿉니다 |

## 6. 점검
- 모든 페이지를 390px·1280px로 열어 가로 넘침 0, 콘솔 오류 0, 빈 캐릭터 그림 0.
- 긴 URL은 `overflow-wrap:anywhere`.
- 바꾼 페이지의 퀴즈 수·지식 색인 노드 수가 그대로인지(본문만 바뀌었는지) 확인.
- 작업 전후 페르소나 평가 점수를 비교해 보고에 한 줄.
- 작업 전후 교수법 기준표 점수(21점 만점)도 함께 보고, 15점 이상이어야 완료.
- 독자를 포기한 사람으로 부르는 별칭 및 같은 뜻의 말 전체 검색 0건(대사·본문·메타데이터·파일 이름·외국어판).

## 7. 함께 쓰면 좋은 작업 (선택)
- **연습(문제풀이) 페이지**: 시험 주간처럼 빈 자리를 "연습"으로 채운다. 1부 원자료 연습문제(보기 고르면 즉시 정답·해설), 2부 업무 장면 계산·사례 문제(입력 채점, 단계별 풀이, 초파리의 흔한 실수, 업무에서는), 주차별 점수(70% 미만은 해설로 안내). 2부 숫자는 예시값이라고 밝힌다.
- **그림 작업 흐름**: 그림 전체 목록(IMG_INDEX) → 만드는 순서대로 프롬프트 모음(IMG_PROMPTS) → 요청 꾸러미 zip(캐릭터 기본 그림 4장 + 요청문 하나 = 생성 도구 대화 하나, 3~5장씩 + 저장 이름 체크리스트) → 검수(비율, 네 캐릭터, 그림 속 글자, 아웃트로 표정이 대결 결과와 맞는지) → 표정이 틀리면 새로 그리지 말고 기존 그림 + 표정 참고 그림을 첨부해 "표정만 편집" 요청 → WebP로 페이지에 내장, 표지에서 목차 썸네일·공유 미리보기를 잘라 냄 → 목록 상태 갱신.
