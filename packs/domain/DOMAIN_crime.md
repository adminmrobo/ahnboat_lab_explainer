# 분야 팩 · AI 범죄학 (`crime`)

AI가 범죄의 비용 구조와 수익 모델을 어떻게 바꾸는지, 그리고 제도·기술·습관이 그 계산을 어떻게 다시 뒤집는지를 다룬다. 범죄경제학(기대효용), 게임이론(신호·검사·협상·협력), AI 분석(탐지·재식별)을 세 가지 분석 도구로 쓴다. 분야 이름 'AI 범죄학'은 이 시리즈의 분류 틀이며, 학계의 공식 분과 이름이라고 쓰지 않는다.

## P1. 분야 신호어 (코어 2-0-1에 더함)

| 강한 신호 (3점) | 보통 신호 (1점) |
|---|---|
| 딥페이크 사기, 보이스피싱, 사회공학, 합성 신원, 명의도용, 랜섬웨어, 자금 세탁, 범죄경제학, 베커 모형, 검거 확률, 억제 효과, 계정 탈취, 비대면 계좌 개설, 라이브니스, 위협 정보 공유 | 보안, 사기, 해킹, 개인정보, 인증, 수사, 처벌 |

자주 함께 오는 보조 분야: 경제학(`econ`, 기대효용·게임이론), 인공지능(`ai`, 이상 탐지·생성 모델), 통계학(`stats`, 범죄 통계 읽기).

## P2. 짝 카드와 연결 상자

| 자리 | 이름 |
|---|---|
| 짝 카드 오른쪽 | "범죄자의 계산서로는" — 그 현상이 p(검거 확률)·f(처벌)·g(이익)·π(성공 확률)·c(비용) 중 무엇을 움직이는지 |
| 파란 연결 상자 | "뉴스·보고서로 읽으면" — 이 개념이 실제 사건 보도, 기관·업계 보고서에서 어떻게 나오는지. **한계 한 줄은 늘 "집계 기준과 분모를 확인한다"** |
| 빨간 연결 상자 | "내 일상에 옮기면" — 개인이 바로 할 수 있는 확인 절차·명의 잠금·신고 경로 |

## P3. 기본 앵커

범죄 장면을 그대로 재연하지 않는다. 앵커는 **연구실 안의 모의 상황**과 **일상의 확인 장면**에서 고른다.

| 주제 | 주 앵커 | 대응 예 | 캐릭터 역할 |
|---|---|---|---|
| 기대효용·억제 | B 연구실 | 주판봇이 범죄자 대역 X1의 계산서를 주판으로 계산 | X1~X3는 범죄자 대역(방청·진술), 주판봇 계산 |
| 딥페이크·음성 복제 | D 생활 | 가족 목소리 전화, 미리 정한 확인 질문 | 조수(하루) 대응 설계 |
| 사회공학 | D 생활 | 택배·기관 사칭 문자, 콜백 절차 | 인턴 시아 현장 사례 |
| 자동화 공격 | B 연구실 | 로그인 기록 5,000건 속 숨은 공격 찾기 | 초파리 연구원 분석 |
| 금융 범죄·세탁 | C 매출 기록 | 쓸 수 있는 돈이 되기까지의 경로를 상자 흐름으로 (실제 거래소·지갑 주소 금지) | X3 진술, 모아 제도 |
| 감시·재식별 | B 연구실 | 조각 정보 몇 개로 '세상에 나 하나'가 되는 과정 | 초파리 연구원 |
| 제도 설계 | B 연구실 | 제도를 켜고 끄며 강화학습 에이전트가 배우는 행동 | 박사 정리 |
| 현장 검증 | B 연구실 | 박사가 새 보고서를 책 옆에 대고 대조 | 박사 단독 (연구실 리포트 동향편) |

생물 앵커(A)는 쓰지 않는다.

## P5. 상호작용 모듈 카탈로그

모든 수치는 예시값이며 "모의 데이터(가상)" 표시를 붙인다.

| 모듈 | 조작 | 그림 | 기대 결과·교훈 |
|---|---|---|---|
| 범죄자의 계산서 | p, f, g, c | 기대이익 막대 | 위험 중립 가정에서 f = 100, g = 60, p = 0.3이면 0.3 × (−100) + 0.7 × 60 = 12. p를 0.5로 올리면 −20 |
| 손익분기 검거 확률 | g, f | p* 표시선 | p* = g / (g + f). g = 60, f = 100이면 0.375 |
| 사기 퍼널 | 단계별 통과율 | 깔때기 | 단계마다 두세 배씩만 올라도 곱하면 최종 결과는 크게 벌어진다 |
| 검사 게임 | 검사 비용, 적발 시 손실 | 혼합 전략 확률 | 검사를 늘리면 위반이 줄지만 0이 되지는 않는다 |
| 몸값 협상 | 백업 여부, 지급 확률 | 협상 나무 | 백업이 있으면 위협의 가치가 떨어진다 |
| 고정 규칙 vs 행위 탐지 | 공격의 학습 라운드 | 두 선 그래프 | 공격이 배우면 고정 규칙은 빠르게 무력해진다 |
| 재식별 | 공개 조각 수 | 후보 수 막대 | 조각 몇 개면 후보가 1명으로 준다 |
| 확인 절차 | 확인 질문 사용 여부 | 정답률 막대 | 감각 훈련보다 절차가 효과가 크다 |
| 강화학습 제도 실험 | 제도 켜기·끄기 | 에이전트 행동 비율 | 도덕 선언만으로는 행동이 바뀌지 않고, 강제력이 붙은 인센티브가 바꾼다 |

## P7. 자주 틀리는 단정과 안전 규칙

| 틀린 단정 / 위험 | 바른 표현 / 규칙 |
|---|---|
| "AI 범죄는 막을 수 없다" | "비용 구조가 바뀌었다. 제도·기술·습관이 겹치면 계산서를 다시 뒤집을 수 있다" |
| "처벌만 강하게 하면 된다" | "처벌의 강도보다 확실성이 억제력이 크다는 연구가 반복해서 보고되었다(출처와 함께)" |
| 업계 보고서 수치를 공식 통계처럼 쓰기 | 집계 주체·분모·자료 성격을 함께 적는다 |
| 분모가 다른 두 비율을 같은 것처럼 비교 | 분모를 문장에 적는다 |
| 범죄 수법의 실행 절차·도구 이름·명령어 | **싣지 않는다.** 작동 원리 수준까지만 |
| 실제 피해자·용의자를 특정할 수 있는 정보 | 싣지 않는다. 보도된 사건도 개인 식별 정보는 뺀다 |
| 특정 국가·집단을 범죄와 묶는 표현 | 쓰지 않는다. 출처가 밝힌 조직·사건 단위로만 |
| "세계 최초", "아무도 다루지 않은" | "이 시리즈가 아직 다루지 않은" |

## P9. 온톨로지 확장

| 항목 | 값 |
|---|---|
| 주로 쓰는 클래스 | `Concept`, `Method`(탐지·대응 방법), `Theory`(베커 모형 등), `Indicator`(피해 비중·차단율), `Standard`(법·규제, `asOf`·`jurisdiction` 필수), `Claim`(사건·통계, `asOf` 필수), `Question` |
| 주로 쓰는 관계 | `measuredBy`, `governedBy`, `appliesIn`, `supersededBy`(통계 갱신), `contrastsWith`(공격 수법 ↔ 대응), `addressedBy`(취약점 → 대응), `raises` |
| 범죄자의 계산서 기호 | 개념이 움직이는 변수를 `crimeVar` 필드에 적는다: `p`, `f`, `g`, `pi`, `c` 중 하나 이상과 방향(`up`/`down`) |
| 책과의 대조 | 현장 검증 페이지는 대조 항목마다 `Claim`을 만들고, 책 장 문헌(`lab:work/ahn2025aicrime`)에 `assertedIn`으로 잇는다 |
| `family` 값 | `ai-crime-basics`, `crime-economics`, `crime-games`, `synthetic-media`, `social-engineering`, `automated-attacks`, `financial-crime`, `surveillance-privacy`, `detection-response`, `institutions-policy`, `personal-defense`, `future-threats`, `field-verification` |
| 분야를 넘는 개념 | 기대효용·게임이론은 `econ`과, 이상 탐지·생성 모델은 `ai`와 같은 ID를 쓰고 `domain: ["crime", "econ"]`처럼 두 분야를 적는다 |
| 외부 매핑 | Wikidata. ID는 확인한 것만 |
