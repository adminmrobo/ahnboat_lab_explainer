한 분야의 **뼈대 온톨로지**(영역과 주제 목록)를 먼저 정한다. 그다음 시리즈 페이지들의 꾸러미(O2)를 합쳐 "이 시리즈가 뼈대를 어디까지 채웠나"를 재고, 빈칸에서 다음 페이지를 고르고, 만들고, 다시 잰다. 이 순환을 정해진 절차로 만든 것이 이 장이다. 화면은 `KG_00_coverage.html`(시리즈 커버리지 지도)이고, 순환할 때마다 기록 파일이 남는다.

> **"완성"의 뜻:** 이 시리즈가 뼈대의 모든 주제를 정한 깊이까지 다룬 상태를 말한다. 분야 지식이 완성된다는 뜻도, 분야에 빈 곳이 없다는 뜻도 아니다. 분야 전체가 답하지 못한 열린 문제는 O3장의 `gap` 상태가 맡고, 이 장의 "빈칸"과 섞지 않는다(O5-12).

### O5-1. 전체 흐름

```
P0 뼈대 정하기 ──► P1 꾸러미 만들기 ──► P2 합치기 ──► P3 커버리지 재기
                     ▲  (새 페이지 / 기존 페이지 개조)                │
                     │                                              ▼
                  P6 만들기 ◄── P5 다음 페이지 고르기 ◄── P4 빈칸 나누기
                                                                     
P7 확인 (문헌·외부 ID) ── 어느 단계에서든 따로 돌린다
```

| 단계 | 하는 일 | 입력 | 출력 |
|---|---|---|---|
| P0 | 분야의 영역·주제·선수 관계를 정한다 | 교과서 목차, 강의 계획, 서베이 | `backbone.json` |
| P1 | 페이지마다 지식 그래프와 서지 꾸러미를 만든다 | 페이지 HTML, 등록부 | 꾸러미 ZIP (O2) |
| P2 | 꾸러미를 합쳐 노드·관계·문헌을 하나로 만든다 | 꾸러미 ZIP 여러 개 | 합친 그래프, 충돌 보고서 |
| P3 | 뼈대 주제마다 상태 0~3을 매긴다 | 합친 그래프 + 뼈대 | `coverage.csv`, 지표 6개 |
| P4 | 빈칸을 다섯 종류로 나눈다 | 커버리지 | `gap_report.md` |
| P5 | 점수로 다음 페이지 후보를 고른다 | 빈칸 보고서 | `next_page_card.md` |
| P6 | 제1부 절차로 페이지를 만든다 | 기획 카드 + 자료 | 새 페이지 HTML + 꾸러미 |
| P7 | 문헌 서지와 외부 ID를 확인한다 | 참고문헌 CSL-JSON | `verified` 표시 갱신 |

한 번 돌 때마다 `pipeline_log.json`에 회차를 한 줄 더한다(O5-10).

### O5-2. 기준 수치 (1회차, 2026-10-25)

이 장의 기본값은 첫 측정 결과를 보고 정했다. 꾸러미가 있는 페이지 2개(1번 초파리 뇌로 보는 딥러닝 기초, 2번 초파리 기억 인출 논문)를 뼈대 초안 v0.1(영역 20, 주제 105)에 올렸다.

| 지표 | 값 | 읽는 법 |
|---|---|---|
| 건드린 주제 (상태 1 이상) | 32 / 105 (30%) | |
| 설명한 주제 (상태 2 이상) | 25 (24%) | |
| 근거까지 있는 주제 (상태 3) | 4 | 설명한 25개 중 16%만 출처 있는 주장으로 받쳐짐 |
| 건드린 영역 | 11 / 20 | 9개 영역이 0 |
| 초파리 비유로 덮은 주제 | 13 | 건드린 주제의 41% |
| 합친 노드 · 관계 | 134 · 211 | 페이지당 약 67노드, O1-8 목표(30~80) 안 |
| 두 페이지가 같이 쓴 노드 | 5 | 케니언 세포, 도파민 뉴런, 버섯체, 측각, 동결된 사전학습 가중치 |
| 확인한 문헌 | 11 | 1개(Vaswani 2017)는 쪽수·DOI 미확인으로 남김 |
| 꾸러미가 없는 페이지 | 9 | 3-1~3-8, "신경망은 틀리면서 배운다" |

**수치에서 얻은 규칙** (아래 각 절에 반영):

1. **측정 누락이 가장 큰 오차다.** 3-3(CNN), 3-7(순서 모델), 3-8(어텐션)이 이미 있는데도 시퀀스·어텐션 영역이 0으로 나왔다. 꾸러미가 없는 페이지는 지도에 안 보인다. → 새 페이지보다 **기존 페이지 개조가 먼저**다(O5-8 규칙 S0).
2. **근거 단계가 얇다.** 설명은 했는데 출처 있는 Claim으로 이어지지 않은 주제가 21개다. → 상태 2인 주제마다 출처 있는 Claim을 최소 1개 둔다(O5-4 R5).
3. **비유가 한쪽에 몰린다.** 신경과학과 AI 영역은 83% 채웠지만 단계 4 영역 여섯 개(어텐션, 언어, 생성, 그래프, 시스템, 책임 있는 AI)는 0~14%다. 초파리 비유가 잘 맞는 주제부터 채워진 결과다. → 빈칸 G5(쏠림)를 따로 센다(O5-7).
4. **"언급만" 7개는 대부분 비유 상자에서 나왔다.** 정규화 층, 잔차 연결, 전이 학습, LoRA, 검색 증강 생성, 멀티태스크, 설명 가능성. 이 주제들은 "다음 페이지 후보"이면서 "이미 독자가 이름은 들은 주제"다. → 점수에 가산한다(O5-8).
5. **등록부가 작동한다.** 두 페이지가 해부 개념 5개를 같은 ID로 썼고 충돌은 0이었다. → 개조할 때도 등록부를 먼저 읽는다(O5-4 R4).

### O5-3. P0 · 뼈대 형식 (`backbone.json`)

```json
{"version": "0.1", "name": "딥러닝·AI 영역 뼈대 (초안)",
 "note": "표준 교과서 목차와 분야 구분을 참고해 이 시리즈용으로 만든 작성자 초안. 공식 분류 체계가 아님.",
 "nodes": [
  {"id": "lab:area/math", "type": "Area", "label": {"ko": "수학 기초", "en": "Mathematical foundations"},
   "level": 1, "family": "math", "status": "known", "tier": 1},
  {"id": "lab:topic/linear-algebra", "type": "Topic", "label": {"ko": "선형대수", "en": "Linear algebra"},
   "level": 1, "family": "math", "status": "known", "tier": 2}
 ],
 "edges": [
  {"s": "lab:topic/linear-algebra", "p": "lab:broader", "o": "lab:area/math"},
  {"s": "lab:area/math", "p": "lab:prerequisiteOf", "o": "lab:area/ml-basics"}
 ]}
```

| 항목 | 규칙 |
|---|---|
| 규모 | 영역 15~25개, 영역마다 주제 3~8개, 전체 주제 80~150개 |
| `level` | 1 기초 · 2 핵심 · 3 응용 · 4 최신·심화. 영역 단계와 주제 단계를 따로 매긴다 |
| 관계 | 주제 → 영역 `broader` (주제마다 정확히 1개), 영역 사이·주제 사이 `prerequisiteOf` |
| 도장 | `note`에 "작성자 초안, 공식 분류 체계 아님"을 넣고 화면에도 표시한다 |
| 외부 대응 | ACM CCS, CSO, Wikidata 대응은 P7에서 확인한 것만 `exactMatch`·`closeMatch`로 넣는다. 확인 전에는 비워 둔다 |
| 판 올리기 | 주제 ID는 바꾸지 않는다. 추가는 자유, 삭제 대신 `"deprecated": true`. 판이 바뀌면 `version`을 올리고 `pipeline_log.json`에 적는다 |
| 쪼개기·합치기 | 주제 하나에 페이지 항목이 15개를 넘으면 쪼갤 후보, 3회차 연속 0이고 선수 관계도 없으면 합칠 후보로 보고서에만 적는다(사람이 정한다) |

### O5-4. P1 · 꾸러미 만들기

**새 페이지:** 제2부 O1·O2를 그대로 따른다. 여기에 R3·R5만 더한다.

**기존 페이지 개조:** 이미 공개한 페이지에 `#kg`(지식 색인)와 `#export`(꾸러미) 두 섹션만 덧붙인다. 맨 위 글 표지가 없는 페이지면 표지도 함께 보강한다(본편 18-14·18-15, 또는 이 장을 따로 쓸 때는 끝의 "부록 · 표지 보강").

| # | 개조 규칙 |
|---|---|
| R1 | **본문은 고치지 않는다.** 개념 사다리, 시뮬레이션, Colab 코드, 용어, 참고문헌, 교육자 TIP(A–F 공통 섹션), 아웃트로 모두 그대로. 오타나 사실 오류를 발견하면 고치지 말고 `retrofit_log.md`에 적어 사람에게 넘긴다 |
| R2 | **참고문헌은 페이지에 적힌 것만 옮긴다.** 페이지에 DOI·쪽수·권호가 없으면 빈칸으로 두고 `verified`에 `false`. 저자 이름은 페이지에 적힌 그대로 |
| R3 | **상태 판정을 표로 한다** (아래 표). 애매하면 낮은 쪽 |
| R4 | **등록부를 먼저 읽는다.** 같은 개념이면 같은 ID. 새 ID는 등록부 갱신분으로 함께 낸다 |
| R5 | **상태 2 항목마다 근거를 찾는다.** 페이지 참고문헌 중 그 항목을 뒷받침하는 문헌이 있으면 `Claim` 노드를 만들고 `supports`와 `assertedIn`으로 잇는다. 페이지에 근거가 없으면 만들지 않는다(지어내지 않음) |
| R6 | **뼈대에 걸기.** 항목마다 `broader`로 뼈대 주제 1~2개에 건다. 맞는 주제가 없으면 걸지 않고 `retrofit_log.md`의 "뼈대 밖 항목"에 적는다(P0 판 올리기 후보) |
| R7 | 페이지 끝 순서는 O1·O2와 같다: … → 아웃트로 → `#kg` → `#export` → 바닥글 |

**항목 상태 판정표 (`coverage` 필드):**

| 값 | 기준 | 예 |
|---|---|---|
| `explained` | 정의 문장이 있고, 예시·그림·시뮬레이션·코드 중 하나 이상이 그 개념을 직접 보여 준다 | 3-2의 ReLU: 정의 + 그래프 + 코드 |
| `mentioned` | 이름이나 비유로만 나오고 정의·예시가 없다 | 비유 상자에서 "LoRA와 닮았다"고만 한 경우 |
| (노드 안 만듦) | 목록·각주에 이름만 한 번 지나간다 | 참고문헌 제목 속 단어 |

### O5-5. P2 · 합치기

| 경우 | 처리 |
|---|---|
| 같은 노드 `id` | 하나로 합친다. 등장 페이지 목록을 모으고, `coverage`는 높은 쪽(`explained` > `mentioned`) |
| 같은 관계 (`s`, `p`, `o` 같음) | 하나로, 페이지 목록만 모은다 |
| 같은 `id`인데 종류나 한글 이름이 다름 | **충돌 보고서**에 올린다. 등록부에 있으면 등록부 쪽, 없으면 먼저 만든 페이지 쪽을 임시로 쓴다 |
| 다른 문헌 `id`인데 DOI가 같음, 또는 제목·연도가 같음 | 중복 후보로 보고서에 올린다. 자동으로 합치지 않는다 |
| 같은 문헌 `id`인데 제목·연도가 다름 | 충돌 보고서. 확인된(`verified:true`) 쪽을 쓴다 |

합친 결과는 그대로 O3장 연구 지식 지도의 입력이 된다.

### O5-6. P3 · 커버리지 재기

**주제 상태 (0~3):** 뼈대 주제 `t`에 `broader`로 걸린 항목들 중 가장 높은 값.

| 상태 | 이름 | 조건 |
|---|---|---|
| 0 | 없음 | 걸린 항목 없음 |
| 1 | 언급 | 걸린 항목이 모두 `mentioned` |
| 2 | 설명 | `explained` 항목이 1개 이상 |
| 3 | 설명+근거 | `explained` 항목 중 하나 이상이, 출처(`source`)가 있는 `Claim`의 `supports` 대상 |

**주제 표시:** 걸린 항목 중 `BioAnalogue`이거나 `bioAnalogueOf` 관계가 있으면 "초파리 비유"로 표시한다.

**영역 채움:** 영역 안 주제 상태 합 ÷ (주제 수 × 3). 영역 상태는 주제 상태의 최댓값이다.

**지표 6개** (KG_00 상단, `pipeline_log.json` 회차마다 기록): 건드린 주제 수, 설명 비율, 근거 주제 수, 건드린 영역 수, 초파리 비유 주제 수, 합친 노드·관계 수.

### O5-7. P4 · 빈칸 다섯 종류

| 코드 | 이름 (화면 문구) | 찾는 조건 | 다음 행동 |
|---|---|---|---|
| G1 | 이 시리즈가 아직 다루지 않은 영역 | 영역의 모든 주제가 0 | 영역 입문 페이지 |
| G2 | 바로 다음에 쓰기 쉬운 주제 | 선수 주제(또는 선수 영역)가 2 이상인데 이 주제는 0 | 다음 페이지 1순위 |
| G3 | 언급만 한 주제 | 상태 1 | 기존 페이지 심화 상자, 또는 다음 페이지에 포함 |
| G4 | 근거가 빠진 주제 | 상태 2 (3이 아님) | P1 R5를 다시 적용, 또는 출처 상자 보강 |
| G5 | 쏠림 | 영역 채움이 시리즈 평균의 2배 이상인 영역, 또는 비유 주제 비율이 70%를 넘는 영역 | 그 영역의 새 페이지는 미룬다. 비유 앵커를 다른 것으로(7장) |

KG_00 v3에는 G1~G3가 있다. G4·G5는 다음 판에 넣는다(O5-11).

### O5-8. P5 · 다음 페이지 고르기

**순서 규칙 (점수보다 먼저):**

- **S0 개조 먼저.** 꾸러미가 없는 기존 페이지가 있으면, 새 페이지보다 그 페이지 개조를 먼저 권한다. 개조 순서는 "채울 것으로 보이는 영역 수 × 참고문헌 수"가 큰 순서. 이때 영역 추정은 섹션 제목만 본 것이므로 "추정·미검증"으로 표시한다.
- **S1 겹침 확인.** 후보 주제를 이미 `explained`로 다룬 페이지가 있으면 새 페이지 대신 그 페이지의 심화편으로 연결할지 먼저 묻는다.

**후보 주제 점수 (상태 0 또는 1인 주제마다):**

```
점수 = 3 × [G2 다음 칸]
     + 2 × [G1 영역에 속함]
     + 1 × [G3 언급만]
     + 1 × [같은 영역에 상태 0~1 주제가 3개 이상 → 한 페이지로 묶기 좋음]
     − 1 × [G5 쏠림 영역]
     − 1 × [주제 level − 설명한 주제들의 평균 level ≥ 2 → 너무 앞섬]
```

가중치는 기본값이다. 사용자가 바꾸면 `pipeline_log.json`의 `weights`에 남긴다.

**페이지로 묶기:** 영역마다 점수 합을 내고, 상위 영역에서 점수 높은 주제 3~6개를 한 페이지로 묶는다. 묶은 주제들은 선수 관계로 이어져 있어야 한다(개념 사다리가 되도록).

**기획 카드 `next_page_card.md`:**

```markdown

- 제목 후보: {두세 개}
- 채울 주제: {주제 (현재 상태 → 목표 상태)} …
```

### C-3. 지시문 만들기 (AI가 페이지를 읽고 채운다)

### C-5. 프롬프트

**표지 지시문만 받기**
```
첨부한 기존 페이지들(목차 포함)을 읽고, "부록 · 표지 보강" C-1~C-3 규칙으로 표지 지시문을 만들어 줘.
한 파일 COVER_PROMPTS_{시리즈}.md에 모으고, 표지마다 "Genspark에 붙여 넣기" 칸(한국어 지시 + 영어 프롬프트)과 대체 글을 넣어 줘.
표지끼리 장소·포즈·소품이 겹치지 않게.
```

**받은 표지 반영하기**
```
첨부한 표지 그림을 C-4 절차로 반영해 줘. 그림 → 페이지 짝: {cover_index.png → index.html, …}
먼저 확인 결과(비율·크기·글자·네 캐릭터)를 보여 주고, 문제가 없으면 넣는다. <!-- lab-cover --> 블록 밖 본문은 바꾸지 않는다.
```
