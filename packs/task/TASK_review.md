1부는 저자의 **범용 평가 프롬프트**를 그대로 실었다. 해설 페이지뿐 아니라 강의 자료·보고서·앱에도 그대로 쓴다. 2부는 이 저장소의 해설 대시보드를 검수할 때 1부에 더하는 규칙이다. 두 부가 다르면 2부가 우선한다(해설 대시보드에 한해).

# 1부 · 범용 평가 프롬프트 (원문)

# 페르소나 기반 다관점 평가 프롬프트 (범용)

> 사용법: 아래 `## 입력` 섹션의 `{{ }}` 항목만 채운 뒤, 평가 대상(파일·링크·설명)과 함께 이 프롬프트 전체를 AI에게 전달한다. 나머지 섹션은 수정하지 않아도 된다.

---

## 역할

당신은 여러 사용자 관점을 오가며 결과물을 냉정하게 검토하는 **평가 설계자이자 리뷰어**다. 평가 대상을 실제로 사용할 사람들을 페르소나로 구체화하고, 각자의 입장에서 대상을 **실제 기능·내용 기준으로** 평가한 뒤, 수정·보완 과제를 우선순위로 정리한다.

---

## 입력

| 항목 | 내용 |
|---|---|
| 평가 대상 | {{예: 교육용 인터랙티브 대시보드 2종 / 웹 서비스 / 강의 자료 / 보고서 / 앱 시제품}} |
| 대상 개수·이름 | {{예: 1번 "OOO", 2번 "OOO"}} |
| 제작 목적 | {{이 결과물이 달성하려는 것}} |
| 의도한 사용자 | {{주 대상 / 부 대상. 모르면 "추정해서 제안"}} |
| 페르소나 수 | {{기본 6명. 4~8명 권장}} |
| 반드시 포함할 페르소나 | {{예: 교수, 현업 실무자. 없으면 "자유"}} |
| 평가 척도 | {{기본: 5점 만점, 0.5 단위}} |
| 작성자와의 관계 | {{"내가 만든 결과물" / "타인의 결과물"}} |
| 추가 제약 | {{예: 예산·기간·기술 스택, 수정 가능한 범위}} |

## 진행 원칙

1. **실물 기준 평가**: 대상에 실제로 존재하는 기능·문장·수치·화면을 근거로 평가한다. 추측으로 기능이 있다고 가정하거나 없는 문제를 만들지 않는다. 확인할 수 없는 부분은 `확인 필요`로 표시한다.
2. **비판 우선**: 작성자가 본인이거나 AI 자신이 만든 결과물이라면 칭찬보다 빈 곳·오류·오해 소지를 찾는 데 더 무게를 둔다. 좋았던 점도 쓰되, 문제점이 더 구체적이어야 한다.
3. **페르소나의 목소리 유지**: 각 페르소나는 자기 배경·목표·어휘로 말한다. 같은 지적을 여러 페르소나에 복사해 넣지 않는다. 겹치는 지적은 종합 단계에서 합친다.
4. **구체성**: "설명이 부족하다" 대신 "어느 부분의 어떤 용어가 설명 없이 나온다"처럼 위치와 대상을 짚는다. 수정 제안도 "무엇을, 어디에, 어떻게" 수준으로 쓴다.
5. **정확성 검토 포함**: 사실·수치·전문 개념이 들어 있다면 해당 분야 전문가 페르소나가 정확성을 따로 점검한다. 근거 없는 수치, 논쟁 중인 주장을 단정한 부분, 모형·예시를 실제 데이터처럼 보이게 한 부분을 찾는다.
6. **점수 보정**: 점수는 페르소나별 기대치 기준이다. 모든 항목에 4점 이상을 주는 식의 후한 평가를 피하고, 점수와 한 줄 총평의 논리가 맞아야 한다.

## 작업 단계

### 1단계. 대상 파악 (내부 작업, 3~5줄 요약만 출력)
- 대상의 구성(섹션·기능·화면)과 핵심 메시지를 파악한다.
- 대상이 여러 개면 각각의 성격 차이를 한 줄씩 적는다.

### 2단계. 페르소나 설계
다음 축이 고르게 섞이도록 페르소나를 만든다.
- **숙련도**: 입문자 ↔ 전문가
- **관계**: 배우는 사람 / 가르치는 사람 / 업무에 적용하는 사람 / 인접 분야 전문가
- **목적**: 이해, 정확성 검증, 수업·교육 활용, 업무 적용, 다른 주제로의 확장

각 페르소나는 이름표(A, B, C…), 구체적 배경(학년·경력·사용 도구 수준 등), 이 자료에서 원하는 것을 가진다.

### 3단계. 페르소나별 점수 평가
대상별 점수와 한 줄 총평을 쓴다. 한 줄 총평에는 가장 결정적인 장점과 단점이 함께 들어간다.

### 4단계. 페르소나별 상세 평가
각 페르소나에 대해 `좋았던 점 / 부족하거나 문제인 점 / 수정·보완 제안`을 쓴다. 문제점과 제안은 1:1로 대응되도록 한다.

### 5단계. 종합 보완 과제
- 모든 페르소나의 제안을 합치고 중복을 병합한다.
- 우선순위는 **(영향받는 페르소나 수 × 문제의 심각도) ÷ 수정 난이도**를 기준으로 판단한다. 정확성 오류나 핵심 개념 누락은 페르소나 수가 적어도 상위에 둔다.
- 난이도는 `하 / 중 / 상`, 외부 자료나 데이터가 필요하면 괄호로 밝힌다.

### 6단계. 정리
- 페르소나를 성향별 무리(예: 입문자 vs 전문가, 학습자 vs 교육자)로 묶어 평가가 어떻게 갈렸는지 설명한다.
- **비용 대비 효과가 가장 큰 1~3개 과제**를 먼저 고칠 것으로 제안한다.

# 2부 · 해설 대시보드 검수 (ai-lab-explainer 연결)

## R0. 1부와 무엇이 다른가

| 1부 | 2부에서 |
|---|---|
| 페르소나를 매번 설계 | **분야별 고정 여섯 명**을 쓴다. 같은 사람이 채점해야 페이지끼리, 판끼리 점수를 견줄 수 있다 |
| 입력표를 손으로 채움 | 페이지의 `page-meta`에서 읽고, 없을 때만 묻는다 |
| 정확성 검토의 기준이 일반적 | 본 스킬과 분야 팩의 금지 단정, 기준일·관할, 논쟁 주제, 캐릭터 규칙을 점검 목록으로 |
| 이전 점수 비교 없음 | 이전 점수와 변화(▲▼–), `review_log.json` 기록 |
| 기계로 확인할 것도 페르소나가 판단 | 페르소나 평가 **전에** 기계 점검(R2) |

## R1. 입력 채우기

| 1부 입력 | 해설 대시보드에서 |
|---|---|
| 평가 대상, 대상 이름 | `page-meta`의 `title`, `number` (없으면 `<title>`) |
| 제작 목적 | 히어로의 핵심 질문 + `page-meta.about` |
| 의도한 사용자 | 입문자 기준 + 전문가용 펼침 (본 스킬 2-1) |
| 페르소나 수·반드시 포함 | **분야 고정 여섯 명**: 인공지능은 본 스킬 14-1, 다른 분야는 분야 팩 P8. 두 분야에 걸치면 주 분야 4명(A·B·C·D) + 보조 분야 2명(C·E) |
| 평가 척도 | 5점 만점, 0.5 단위 |
| 작성자와의 관계 | "내가 만든 결과물" (1부 원칙 2, 비판 우선) |
| 분야·형식 | `page-meta` 또는 노드의 `domain`. 없으면 본 스킬 2-0대로 묻는다. 형식(대결형·미션형)은 페이지 구조로 판단 |

- 1부 2단계(페르소나 설계)는 고정 페르소나로 대신한다. 사용자가 다른 사람을 원하면 **2명까지 더하되** 점수 비교(R4)에서는 뺀다.
- 페르소나 배경은 고정 표의 한 줄을 1부 1번 표 형식(배경, 원하는 것)으로 풀어 쓴다.

## R2. 기계 점검 (페르소나 평가 전에)

실행 환경(브라우저, 파이썬)이 있으면 실제로 돌린다. **없으면 "실행 못 함"으로 쓰고 통과로 쓰지 않는다.**

| # | 점검 | 기준 |
|---|---|---|
| M1 | 콘솔 오류 | 0 (글꼴 네트워크 오류 제외) |
| M2 | 폭 390px 가로 넘침 | `scrollWidth === 390` |
| M3 | 외부 요청 | 글꼴(번역판은 언어별 글꼴)뿐 |
| M4 | 브라우저 저장소 | 본 스킬 12-2 예외(언어 기억·완료 표시) 밖 사용 0 |
| M5 | 데이터 블록 | `kg-raw`, `kg-ld`, `refs-csl`, `page-meta`가 있고 `JSON.parse` 통과. 끊긴 관계 0 |
| M6 | 그림 키 | 모든 `data-img` 키가 이미지 명세서·캐릭터 팩 `expression_map.json`에 있음 |
| M7 | 금지 표현 검색 | "혁명적", "완벽한", "아무도", "미개척", "최초", "세계 최초" (본 스킬 17장, O5-12) |
| M8 | 번역판 | 화면·`alt`·`aria-label`에 남은 한국어 0 (지시서 14-5 예외만) |
| M9 | 개조한 페이지 | `onto-retrofit/tools/check.py`로 본문 차이 0 |

결과는 1부 0번 요약 바로 아래에 표로 붙인다(통과/실패/실행 못 함 + 근거 한 줄).

## R3. 정확성·규칙 점검 목록 (전문가 페르소나 C가 맡는다)

| 묶음 | 확인할 것 | 근거 |
|---|---|---|
| 수치 | 화면 수치가 사실 카드·코드 결과와 같은가, 논문 수치를 반올림하지 않았나 | 본 스킬 10-1, 지시서 2-3 |
| 도장 | 설명용 그림·값에 도장, 바닥글 "설명용 모형인 것" | 10-2 |
| 금지 단정 | 인공지능 10-5, 분야 팩 P7, 데이터가 있으면 통계 팩 P7 | 10-5, 19장 |
| 시점·관할 | 공식 통계·기준서·세율에 기준일·관할·단위 | 10-6 |
| 논쟁 주제 | 정책·학파 질문에 승패 판정 없음, 두 견해 같은 분량 | 6-4 |
| 비유 | 비유마다 한계 한 줄, 주제와 같은 영역의 비유가 아닌가 | 7-2 |
| 캐릭터 | 형식별 자리(C2), 판정은 박사만, 결과 전 표정, 숫자 발표는 한 명, 주판봇 대사에 실제 기업·지수 없음, 박사·조수 뒤집기 없음 | 캐릭터 팩 C2·C5, 5-5, 5-8 |
| 재무·투자 | "투자 자문 아님" 문구 | 5-5 |
| 출처 | 출처 없는 Claim 0, 지어낸 DOI·쪽수 0 | O2-4, O2-7 |

찾은 문제마다 **섹션 id**(예: `#lv3`)를 적는다.

## R4. 출력 (1부 형식에 더하는 것)

- 0번 요약 아래: **기계 점검 결과** 표 (R2).
- 2번 점수표: 이전 점수가 있으면 열을 더한다. 예: `| 페르소나 | 이번 | 이전 | 변화 | 한 줄 총평 |`, 변화는 ▲ 0.5 / ▼ 1.0 / –.
- 3번 상세 표: "부족하거나 문제인 점"에 섹션 id.
- 4번 과제 표: "근거" 열(R3 묶음 이름 또는 본 스킬 절 번호). 정확성·규칙 위반은 영향 페르소나 수와 상관없이 1순위 묶음.
- 5번 정리: 먼저 고칠 1~3개 + "다시 검수할 때 볼 것".

## R5. 반영과 재평가

1. 사용자가 고른 과제만 고친다. 고칠 때는 본 스킬 15-4(고칠 점 / 바꾸지 말 것)를 쓴다.
2. 고친 뒤 R2 기계 점검을 다시 돌린다.
3. **같은 페르소나**로 다시 채점해 2번 표에 변화를 보인다. 고치지 않은 곳의 점수가 바뀌면 이유를 한 줄 적는다.
4. 고친 것 밖에서 달라진 곳이 생기면(diff) 숨기지 않고 알린다.

## R7. 프롬프트

**검수만**
```text

```

**검수 + 반영**
```text
위 검수 결과의 과제 {번호들}만 반영해 같은 파일 전체를 내 줘(본 스킬 15-4).

```

**시리즈 여러 페이지 비교**
```text
첨부한 HTML {n}개를 같은 고정 페르소나로 검수하고, 페이지별 점수를 한 표로 비교해 줘.

```

**교차 검수 (권장)**
페이지를 만든 대화와 **다른 대화(가능하면 다른 모델)**에서 검수한다. 만든 맥락을 모르는 쪽이 빈 곳을 더 잘 찾는다. 이때 본 스킬, 캐릭터 팩, 해당 분야 팩, 이 검수 팩을 함께 준다.
